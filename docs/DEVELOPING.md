# Developing Compass

Export formats, debug launch options, and signing and installing. Read [PERFORMANCE.md](PERFORMANCE.md) before runtime feature work for caps, benchmark commands and regression checks. Build Debug for sandbox tools; install Release for everyday use.

## Monarch export formats

- Balances: `Date,Balance,Account`, ISO dates, plain decimals, CRLF, no BOM. Debts already negative; overpaid cards positive. Account names look like `Name (...1234)` and some have trailing spaces.
- Transactions: `Date,Merchant,Category,Account,Original Statement,Notes,Amount,Tags,Owner,Reviewed,Id`. ISO dates, negative amounts for money out, `Id` unique per row.

## Debug-only launch options (sandbox data only, compiled out of release builds)

Build Debug, then run the binary with the options below:

```bash
xcodebuild -project Compass.xcodeproj -scheme "Compass Sandbox" -derivedDataPath build/debug.noindex build
APP="build/debug.noindex/Build/Products/Debug/Compass Dev.app/Contents/MacOS/Compass Dev"
"$APP" --sandbox --unlocked --seed-demo
```


- `--sandbox`: separate store (`Compass-Sandbox.store`) and Keychain entry. Use for all testing. Reminders are made-up samples in the sandbox and EventKit is never touched, so no debug run asks for access. Compass Dev without `--sandbox` asks for Reminders access separately from the installed app, because it's a different app to macOS.
- `--unlocked`: skip the lock, for driving the UI.
- `--self-check-store`: only the store checks, no SimpleFIN token needed (also part of `--self-check`): the Playbook survives a migration that adds models, and a build missing one of the store's models refuses the store and leaves it alone.
- `--open-goal "<goal name>"`: Goals opens on the page of the goal with that exact name (once, at launch), so a snapshot can render a goal's page: `--open-goal "Emergency fund"`. Needs `--sandbox`; a name that matches no goal does nothing.
- `--open-search "<text>"`: the search panel opens at launch with that typed, so a snapshot can render it: `--open-search "co"`. Needs `--sandbox`.
- `--self-check <demo token>`: runs app-level checks inside the real app, against throwaway stores and Keychain entries: the M1 checklist's data path, M3 import and pins, M5 import, filing, transaction sync, merge and dedupe, transfers after a sync, the budget sheet, refiling and category renames, a reward photo, Life (goals, vision, habits, a quarter reminder's money link), backup and linked goals. Prints a PASS/FAIL line per check (every failure has one, counted once), then quits.
- `--seed-demo`: a separate demo store (`Compass-Demo.store`) with three years of fake history (the last three days waiting in review), sample goals, a year of transactions, transfers, Life and habits, made-up pay settings (paid every other Thursday, paychecks arriving the Tuesday before) and no paystubs, for design review. Each seed step adds only what's missing, and demo stores from older builds are upgraded (paychecks, the Rewards Card's history).
- `--reset-demo` (with `--seed-demo`): deletes the demo store and its cache before it opens, so the seed starts over.
- `--appearance light|dark`: force the appearance.
- `--open-review "<merchant>"`: opens a waiting Review row’s details by its exact merchant, once when Review renders. Needs `--sandbox`; no match does nothing. `--snapshot-defaults review.selectFirst=true` selects the first categorized waiting row for checking the top bar; both are Debug-only presentation helpers and do not file transactions.
- `--open-transaction "<merchant>"`: opens the exact merchant from the newest transaction page in the Transactions details panel, for snapshots. Use `--snapshot-defaults transactions.summary=true` to render the expanded summary in a narrow window.
- `--scroll-test`: the Money overview scrolls itself to the bottom and back every few seconds until quit, so Instruments can profile scrolling with no one at the trackpad: `xcrun xctrace record --template 'Time Profiler' --time-limit 18s --output scroll.trace --launch -- "<app binary>" --sandbox --unlocked --seed-perf --scroll-test` on a perf build.
- `--auto-sync`: lets a sandbox run sync once a day on its own, as the installed app does. Runs that drive the app (`--self-check`, `--perf-run`, `--seed-perf`, `--seed-demo`, `--seed-only`) never auto-sync.
- `--snapshots <folder>`: renders every screen and each Settings tab offscreen to PNGs (works with the screen locked), then quits. Numbers wait for a net worth computed from the store after the demo seed. Options: `--snapshot-screens money,spending` (screen names also include `settings`, `menubar` for the menu bar panel's cards, and `lock`; the last two are drawn by default when no list is given), `--snapshot-size 1440x1800`, `--snapshot-defaults textSize=larger,accounts.expanded.cash=true` (an accent: `accent=iris`; typefaces: `typeface.display=charter,typeface.text=avenirNext`) (launch-argument domain: this run only, never saved; numbers stored as numbers), `--snapshot-suffix name`. Files are named after the appearance drawn (`--appearance`, else the Appearance setting, else the Mac's). Each Settings tab always gets its own image (`settings-appearance-dark.png`), in the main frame with its native selector at the requested size. The `settings` screen image also shows the saved tab. Debug builds may write under `/private/tmp` for this (`App/CompassDebug.entitlements`).
- Rendering at 1x: copy `Compass Dev.app` somewhere temporary, set `NSHighResolutionCapable` to false in its Info.plist, re-sign it ad hoc with its own entitlements (`codesign -d --entitlements :-`, then `codesign --force --deep --sign - --entitlements`), and run `--snapshots` from the copy. Delete the copy afterwards.
- `--seed-perf`: a separate store (`Compass-Perf.store`) with the M6 benchmark data (add `--seed-only` to seed and quit). `--perf-run` then times launch, every screen, coming back to Spending and Transactions, opening ⌘K search and typing in it, stepping Spending's Over time back a month three times (with main-thread busy time, wakes and the longest stretch, which show what an animation costs), switching Spending's view and back, chart views, ranges and idle memory, and prints `[perf]` lines; a timing during which Spending or Transactions showed a loading line ends "showed loading". Build optimized (`SWIFT_OPTIMIZATION_LEVEL=-O`, `SWIFT_COMPILATION_MODE=wholemodule`) for meaningful numbers. The output is observational: budget breaches do not change the exit code. Follow PERFORMANCE for complete-run checks, repeated comparisons and the known memory/stall exceptions; Settings/menu bar and immediate-after-launch search are not covered by this timing loop.

## Claude's endpoint (MCP)

- Compass serves MCP (JSON-RPC over HTTP, plain JSON replies, no event stream) on `127.0.0.1` only while Settings > Security > "Allow Claude access" is on: port 52741 for the installed app, 52742 for a sandbox debug run, 52743 for a debug run on the Dev store. Every request needs `Authorization: Bearer <key>`; a missing or wrong key gets 403, not 401, so clients don't go looking for OAuth. Notifications get 202, GET gets 405.
- The `initialize` reply's instructions (`ClaudeTools.instructions(for:)`) name the owner from Settings › Profile, or say "the owner" while no name is set (the default name is "You"). Tool descriptions refer to the owner as "they".
- The key lives in the Keychain (account `claude-endpoint`); New Key replaces it, and a key is made only when none is saved. If the Keychain refuses to read a saved key (after a reinstall, say), every request gets 403 and Settings says so, rather than a new key silently cutting off every Claude set up with the old one. A sandbox debug run's key is always `compass-sandbox`, for scripted checks: `"$APP" --sandbox --seed-demo --background -claude.enabled YES`, then `curl -X POST http://127.0.0.1:52742/mcp -H "Authorization: Bearer compass-sandbox" -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'`.
- Claude Code connects directly (`claude mcp add --scope user --transport http …`, copied from Settings; never `--scope project`, which would put the key in the repo). Claude desktop launches the bridge `Contents/MacOS/compass-mcp` (the `Bridge/` target, not sandboxed) with `COMPASS_PORT`, `COMPASS_KEY` and `COMPASS_BUNDLE_ID` in its config entry. The bridge forwards one JSON-RPC line at a time and, if nothing answers, opens the Compass it lives in by path (`open -g -a <its .app> --args --background`, never by bundle ID) and retries for about 15 seconds. It tells Claude the tool list can change (`tools.listChanged`), asks for the list every minute, and sends `notifications/tools/list_changed` when an install changed it, so a long-running Claude picks up new tools without a restart.
- Read tools (listed in `ClaudeReadTools.swift`): `overview`, `net_worth` (with 3M to 5Y changes), `net_worth_history` (range, by day, week or month, total or by class; by day it's the chart's 120 averaged points), `accounts`, `account_history`, `goals`, `goal_history`, `contributions`, `monthly_review`, `budget`, `spending`, `transactions` (text, category or "unfiled", month, from/to, account, direction, amount range, has_note, one_off, reimbursable, note_text, limit; each row has its id, note and flags), `categories`, `reminders`, `habits`, `vision`, `pay`, `notes` (topic, title and body), `playbook` (entries, sizes and the Today line), `calendar` (up to 92 days) and `free_time`. Amounts are strings with two decimals; debts read as what's owed; dates are ISO local days and times carry your offset. Account names drop trailing number fragments ("(...1234)"); institutions and SimpleFIN IDs are never sent; Compass account, goal and editable-object ids are exposed where tools need them. Calls that read every balance or transaction fetch in a context of their own off the main thread. Errors come back as `{"error": "..."}` text Claude can act on, marked `isError`. `reminders` (with notes, and `doneLately`, the last two weeks' ticked-off reminders), `habits`, `pay`'s expected items and the Compass calendar's events in `calendar` carry ids for the write tools, and `accounts` says which are synced.
- Write tools (`ClaudeChangeTools.swift`, rules in Core's `ClaudeRules`), marked `readOnlyHint: false` (and `destructiveHint: false` for the ones that only add): `create_goal`, `update_goal`, `add_reminder`, `edit_reminder`, `complete_reminder`, `add_habit`, `check_in_habit`, `edit_vision`, `edit_bets`, `edit_transaction` (note, one_off, reimbursable, reimbursable_amount, paid_from_goal (a goal's name or id, or "none") and paid_from_goal_amount, category; a category must already exist, and no merchant rule is learned), `set_budget_amount` (what: flexible, bill, income or savings; name; amount or "remove"; month; scope onward or this_month), `set_budget_role` (category, role, expected, month), `create_event`, `move_event`, `delete_event`, `add_note`, `edit_note`, `delete_note` (in `ClaudeNoteTools.swift`), `add_playbook_entry`, `edit_playbook_entry`, `done_playbook_entry`, `set_size`, `delete_playbook_entry`, `remove_size` (in `ClaudePlaybookTools.swift`; steps take `days` as mon to sun), `edit_event`, `move_reminder`, `delete_reminder`, `uncomplete_reminder`, `edit_habit`, `archive_habit`, `delete_habit`, `remove_check_in`, `retire_goal`, `set_reward` (goal, or reminder for a This Quarter reminder with a target; `reminders` and `vision` show its reward), `set_expected_pay`, `edit_expected_pay`, `remove_expected_pay`, `edit_pay_settings`, `create_account`, `rename_account`, `archive_account`, `update_balance` (in `ClaudeUpkeepTools.swift`), `set_merchant_rule`, `delete_merchant_rule`, `create_category`, `rename_category`, `merge_category`, `add_transaction` (amount signed, money out negative; manual accounts only; external id `claude-…`), `split_transaction` (parts as {category, amount} without signs; empty takes the split off) and the read tool `merchant_rules` (in `ClaudeCategoryTools.swift`; `add_reminder` and `edit_reminder` take `notes`, and `complete_reminder` ticks repeats), `undo_change`, plus `changes` (read-only) to list them. Arguments a tool doesn't take are refused, and an unknown tool (`set_balance`, say) gets a plain-words refusal naming what's read-only. Times take `2026-10-30T09:00` as local time. Each change is a `ClaudeActivityRecord` (not in the backup: undo works against live Reminders and Calendar). The Compass calendar is made on first use in the account new events go to, and its id kept in `calendar.compassCalendarID`, so a calendar of your that happens to be called Compass is never used. In the sandbox, reminders and events changes are in memory and gone at relaunch, so undoing one from an earlier run says it isn't there; a sample repeat ticked moves on a day (daily) or a week and leaves a done copy, as Reminders does.
- In the sandbox, `calendar` and `free_time` read the sample events; the demo seed adds a monthly $750 move from checking to the brokerage and a quarterly dividend, so `contributions` has both sides to split.
- `--background` (any build): no window at launch and no Touch ID until Compass is brought forward. Clicking it in the Dock opens the window.

## Maintainer workflow

The maintainer's own sessions (and agents working in them) skip pull requests:

- `main` is always the newest version. Commit each change to `main` and push `origin/main`; short-lived branches merge back promptly.
- After pushing, install the Release build with the command in [USING.md](USING.md) so the installed app matches `main`. It needs `Config/Local.xcconfig` with the maintainer's team: a different signature loses the Keychain grant for the SimpleFIN access and the Claude endpoint key. Compare `codesign -d -r- /Applications/Compass.app` with the new build's before replacing it if the signing setup changed.
- Relaunch by path (below), never by bundle ID.

## The app icon

The icon is drawn in code (`App/Design/IconArt.swift`). While Compass runs, the Dock shows the mark and accent chosen in Settings. The app copies the choice to the `com.seanjaymanuel.Compass.dock` preferences domain. The install command draws the bundled icon from it (Convergence in cobalt when nothing is chosen), which is what the Dock shows after Compass quits and what Finder, Spotlight and Launchpad show; a new choice reaches them at the next install. A Dock tile plug-in (`DockTile/`, embedded in `Contents/PlugIns`) was meant to follow the choice live, but since macOS 27.2 the Dock doesn't load it for an app that isn't notarized. To re-render the bundled PNGs after changing the drawing (leave off the last argument for Convergence in cobalt):

```bash
xcrun swiftc App/Design/IconArt.swift App/Design/Theme.swift scripts/export-icon/main.swift -o build/export-icon && build/export-icon App/Assets.xcassets/AppIcon.appiconset com.seanjaymanuel.Compass
```

## Signing and installing

Builds are ad hoc signed by default (`Config/Signing.xcconfig`), so a fresh clone builds with no Apple account; ad hoc builds re-prompt for Keychain access after each rebuild. To sign with your own team, copy `Config/Local.xcconfig.example` to `Config/Local.xcconfig` (gitignored) and fill in your team ID; a stable team signature keeps the Keychain grant across rebuilds, and the Release install depends on it. The everyday copy is a Release build installed in `/Applications`; [USING.md](USING.md) has the command. Settings offers eight accent presets (Lagoon, Harbor, Cobalt, Iris, Orchid, Berry, Slate, Graphite in `App/Design/Theme.swift`) plus a custom colour; greens, ambers and reds are kept for status. The icon's mark is drawn in code by `App/Design/IconArt.swift` and chosen in Settings: Convergence (default), Keystone, Fold or Focus. The Dock icon follows the accent and mark while Compass runs. The app copies them to a `<bundle ID>.dock` preferences domain outside its sandbox (a shared-preference exception), and the install command's first step (`scripts/export-icon/main.swift`) draws the bundled icon from it, so the Dock keeps the choice after Compass quits; without a saved choice it draws Convergence in cobalt. A Dock tile plug-in (`DockTile/`, embedded in `Contents/PlugIns`) also draws from that domain and worked on Oct 22, 2026, but since macOS 27.2 (installed Oct 27) the Dock checks the app's notarization and never loads it for this Personal Team build (seen Oct 28: it loads another app's notarized plug-in and doesn't try Compass's). To check whether a later macOS loads it again, `lsof` the `com.apple.dock.external.extra` processes for `CompassDockTile`.

Debug builds from Xcode are a separate app, **Compass Dev** (`com.seanjaymanuel.Compass.dev`), with their own container and Keychain entries, so they can never open the real data.

## The store guard and daily backups

Opening a SwiftData store migrates it to the models the opening build knows and drops the rest. An older build once opened a newer store and SwiftData dropped the models it didn't know. So `CompassStore.container(at:)` reads the store's models from its metadata, plus the fields the last build recorded in `<store>.shape.json` beside it, and refuses (an alert, then quit) when any are unknown to this build (`StoreGuard` in Core). A model or field taken out on purpose goes in `CompassStore.retired`, or every store that has it will be refused. Builds from before Oct 31, 2026 have no guard, so don't keep old builds around: remove a worktree's `build/` when it's done.

The installed app also writes `Backups/compass-backup-YYYY-MM-DD.json` beside the real store once a day (checked every three hours while it runs), keeping two weeks. It's the same bundle as Back Up Now. The app has no restore yet, so putting something back means reading it out of that JSON.

## Relaunching the installed app

A running Compass keeps serving Claude from the old binary after an install, so quit it, wait for that process to exit, and open it by path: `open -g -a /Applications/Compass.app --args --background`. Never use `open -b com.seanjaymanuel.Compass`: it launches whichever copy LaunchServices registered, and once started a stale Release build from a worktree against the real store. The current bridge opens its own app by path as described above. If `lsregister -dump | rg 'path:.*Compass.app'` lists copies outside /Applications, unregister them with `lsregister -u <path>` and run `lsregister -f /Applications/Compass.app` (`lsregister` is in `/System/Library/Frameworks/CoreServices.framework/Frameworks/LaunchServices.framework/Support/`).

## Merchant logos

`MerchantLogos` keeps fetched logos in Application Support/Compass/Logos: `<domain>.ld.png` from logo.dev (with the publishable key saved in Settings > Data, Keychain account `logo-dev-key`), `<domain>.png` from Google's icon service, and `.nologo` for a 404, retried after 30 days. Any other failure (offline, a 401 for a bad key) isn't cached. Settings > Data > Forget Saved Logos clears the folder.
