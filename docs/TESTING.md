# Testing

Compass's logic lives in the `Core` package, and its tests run with `cd Core && xcrun swift test` (CI runs them on every push and pull request, and builds the app).

- **Tests sit at named seams.** Each seam below is a Core type or function with a stated job; tests check that job through its public interface. A new seam needs the maintainer's OK: in a pull request, say what the new tests catch and what they miss.
- **No live services.** Tests never call SimpleFIN; they use the JSON fixtures in `Core/Tests/CoreTests/Fixtures/`. EventKit, Keychain, SwiftData and SwiftUI aren't unit tested; those parts are checked by hand or by the app's `--self-check` (see [DEVELOPING.md](DEVELOPING.md)).
- **Timing tests** (seam 5) catch coarse algorithm regressions on synthetic data. The app-level caps are in [PERFORMANCE.md](PERFORMANCE.md).
- Dates in the list are when a seam was approved or widened (a `+` marks a widening).

Misses an account opened with money from one Compass doesn't track (that money reads as an opening, which it is to you).
